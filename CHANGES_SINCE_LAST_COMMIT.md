# Changes Log & Commit Reference

## Current Working Changes

### 1. Guarantee WYSIWYG Text Color Application & Selection Recovery
- **User Request Addressed:**
  - *"ensure color is correctly applied"*
- **Root Cause & Fixes:**
  - **Selection Retention**: Calling `.focus()` on `editorRef.current` collapsed the browser caret to offset 0 and prevented `activeRange` restoration due to an over-restrictive containment check. Fixed in both [StudentCertificateStudioView.jsx](file:///d:/Shk_Gulfam/Projects/hss_shangus/src/portal/admin/StudentCertificateStudioView.jsx) and [OfficialLetterWriterView.jsx](file:///d:/Shk_Gulfam/Projects/hss_shangus/src/portal/admin/OfficialLetterWriterView.jsx) by unconditionally restoring `activeRange` into the DOM selection upon button click.
  - **Caret Word Expansion**: If the cursor is positioned inside a word without dragging to highlight, clicking a color circle automatically expands the range to select that word before applying color.
  - **Dual-Layer HTML Color Generation**: Enabled `styleWithCSS`, converted any legacy `<font color="...">` tags created by `execCommand` into `<span style="color: ...">`, and implemented a direct DOM range wrapping fallback if `execCommand` fails to wrap text.
  - **Popover Focus Preservation**: Added `onMouseDown={(e) => e.preventDefault()}` on the color popover containers so clicking swatches or popover padding never steals focus or blurs the editor.
  - **CSS Specificity**: Removed hardcoded `#0a192f` from `.body-text-col strong` in [certificateExportUtils.js](file:///d:/Shk_Gulfam/Projects/hss_shangus/src/utils/certificateExportUtils.js), allowing strong text to inherit custom colors in print/PDF.
  - **Word Export Color Support**: Enhanced `sanitizeColor` in [htmlDocxConverter.js](file:///d:/Shk_Gulfam/Projects/hss_shangus/src/utils/htmlDocxConverter.js) to parse `rgb(...)` / `rgba(...)` color strings generated by Chromium and serialize them accurately to docx XML.
